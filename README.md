# Light Template Library (LTL)

Лёгкая коллекция шаблонных контейнеров и утилит на C++ для учебных и встраиваемых задач.

## Описание

Проект предоставляет простую реализацию контейнеров (включая `vector`, `string` и др.) и минимальные вспомогательные заголовки. Цель — дать компактную лёгкую альтернативу стандартной библиотеки STL для обучения и лёгких проектов.

## Основные возможности

- Простая реализация `ltl::vector` с базовыми операциями: push_back/pb, pop_back, erase, размер, итераторы.
- Операторы сложения/умножения для вектора.
- Небольшие утилиты и заголовки в `ltl/`.
- Примеры использования в `light-template-library/light-template-library.cpp`.

## Стек технологий

- C++98/03 совместимый код (без сложных зависимостей).
- Header-only шаблонные реализации.

## Установка (локальная сборка)

1. Клонируйте репозиторий:

```bash
git clone <repo-url>
cd LTL
```

2. Соберите пример (используется обычный компилятор g++/clang++):

```bash
g++ -std=c++11 -Ilight-template-library light-template-library/light-template-library.cpp -o ltl_example
./ltl_example
```

Если ваш компилятор старый, удалите `-std=c++11` или замените на соответствующий стандарт.

## Запуск

После сборки исполняемый файл `ltl_example` демонстрирует работу `ltl::vector`.

## Структура проекта

Ключевые каталоги и файлы:

- `light-template-library/` — пример и проектная обвязка.
  - `light-template-library.cpp` — демонстрация работы.
  - `ltl/` — заголовочные файлы библиотеки (`vector.h`, `string.h`, и т.д.).
- `html/`, `latex/` — сгенерированная документация Doxygen/LaTeX.
- `index.html` — перенаправление на `html/index.html`.
- `LICENSE` — MIT License (в репозитории заменён).

## Переменные окружения

Проект не требует специальных переменных окружения для локальной сборки. При интеграции в CI укажите путь к компилятору или флаг `CXX` при необходимости.

## Тесты

Проекта нет формальных юнит-тестов. Рекомендуется добавить простые тесты с Catch2 или GoogleTest при расширении функционала.

## Важные нюансы и рекомендации

- Код ориентирован на наглядность и компактность, а не на производительность или полную безопасность.
- Некоторые методы не проверяют переполнение во всех местах (например, pop_back без проверки пустоты).
- Исключения используются для проверки границ (`invalid_argument`, `out_of_range`) — подключайте соответствующие заголовки при интеграции.
- Файлы в `html/` и `latex/` содержат сгенерированную документацию Doxygen и могут быть использованы как пример документации.
